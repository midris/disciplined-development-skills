## Recommendation and question

Run **55 new subjects and five read-only output reviews**, retaining the unchanged compact finalist.
This adds selected application and native-selection observations on Codex and Opus, using ten already assessed Opus observations rather than rerunning them.
Selected cells receive five attempts; native attempts support finalist application claims only when complete body delivery before the first relevant action is established.
The question is whether the preferred compact version preserves useful repair behavior on Codex as well as Opus, and selects appropriately on both providers near its applicability boundary.
Effectiveness and consequential output quality lead; complete skill size breaks a supported tie.
This is a relative-version comparison and regression check, without a claim that SSR outperforms unguided work.

Use `candidate` for the preserved comprehensive development base (923 words, SHA-256 `15992341f7ab2fb1e4d8a775092199d7d4e6a9de1167895dbe5a805aeafbd38c`) and `finalist` for the compact skill (814 words, SHA-256 `f1f297f213855f9b53835dd084b2be6d3d9134cadab47babea08cbdaad9a205e`).
Their descriptions remain identical; this proposal changes no skill bytes and allocates no authoring.
The preserved original remains historical comparison evidence; the completed three-way Opus comparison already includes it, so a new original arm is not selected.

## Reuse and applicability boundary

Reuse the ten repair observations from [compact-regression-01](../../skill-studies/sweeping-stale-references/runs/compact-regression-01/compact-regression-01-assessment.md) as repetitions 1–2; collect repetitions 3–5 for those five Opus cells.
Their existing scores and raw bundles remain immutable; recheck the complete inventories and task/project/prompt/body/provider/model/effort/permissions/runtime identities before combining repetitions.
If a relevant identity differs, retain separate strata and revise the scope or seek an explicitly bounded exception; do not silently substitute a new runtime, call the new three observations five, or allocate replacements.
Reuse the completed Opus semantic comparison and its audited review as separate relative-version evidence; do not rerun or pool it with Codex.
The old distant unrelated check remains sanity evidence and does not count toward the new near-boundary case.

The new [verification-only task](../../skill-studies/sweeping-stale-references/cases/invocation-verification/task.md) runs existing tests after an already applied rename, with current code/config/docs consistent and old encodings deliberately retained in archive/vendor files.
It asks for no changed fact, repair, reference audit or proposal; the completed-rename context nevertheless resembles SSR's trigger vocabulary.
The task asks only for the supplied test command and a result report; it neither prohibits repairs nor prescribes a fixed reply.
Unchanged project files/history and an accurate passing-test report are expected observations, not instructions suppressing skill selection.
This avoids treating an actual single-file correction as inapplicable: SSR can legitimately require checking scope for such a change.

The new card prospectively measures avoiding SSR body loading, following CW's delivery-based negative test.
Catalog metadata is allowed; a targeted body read or native Skill invocation is surplus loading, even if subsequently rejected.
Report incidental body exposure, unsuccessful read attempts, partial delivery and task correctness separately rather than inventing intent.
This is stricter than the old unrelated card, which permits exploratory reading; preserve that historical distinction and do not pool their D1 counts.
The negative has D1 only and functional outcome **not measured**; successful test execution is a descriptive task observation, not an SSR repair pass.
The active assessor judges its complete traces; negative outputs are omitted from artifact-review packets because a trace-free reviewer cannot judge D1 and has no functional factor to assess.

## Budget, checkpoint and limits

Requested extension: **55 subjects + 5 evaluators**, no authoring or retry allocation.
Current combined ceilings/spending remain 668 subjects/50 evaluators until approval; proposed ceilings would be **723 subjects/55 evaluators**, with unchanged authoring/retry ceilings of 4 each (**786 total**).
The existing unspent retry/authoring capacity does not authorize any additional action.
Estimated remaining active effort after approval: **120–160 minutes**, including preparation/qualification 15–25, subject waits 40–50, direct assessment 30–40, review/audit 20–30 and closure 15; waits are counted once.
This is an effort forecast, not a dollar estimate or invocation authority.

At the checkpoint, compare whole-output effectiveness and consequential quality across versions/providers, report all functional and selection failures and unknowns, then apply the owner's skill-size tie-breaker only where the evidence supports equivalence.
A material repair/preservation or selection issue requires explanation before an adoption recommendation; minor inventory/verification reporting defects remain visible without automatically triggering another rewrite.
Return an adopt/retain/investigate recommendation and stop for the owner's decision; there is no automatic release or further experiment.

Not selected: an explicit Codex initiating-change cell, fresh original/no-target arms, description authoring, finalist pressure/Shiv/large-accounting batches, Sonnet replication, full-catalog/DD composition, difficult-search or held-out reliability claims.
Pressure and Shiv mechanisms have historical versions' evidence, not finalist validation; this proposal prioritizes the new provider, relative-path/local boundaries and realistic non-use questions already identified as decision-relevant.
Approval accepts those remaining limits; revisit them for a concrete failure, a change depending on them or an expanded use claim.

Lower-cost alternative: **40 new subjects +3 reviews**, keeping Opus's completed two-repetition application/native positives as an explicit final-scope exception and omitting their fifteen top-ups/two expanded reviews.
Its third review packet contains the ten Codex native positive outputs; the two comparison/regression packets stay unchanged, for 30 repair outputs and 90 functional judgments across three reviews.
Both providers' ten negative attempts remain active-session trace assessments under either option.
That saves 17 calls but supplies less variability evidence and departs from the new five-repetition default; it is not the recommended allocation and requires an explicit owner scope choice.
Neither option authorizes collection until selected and frozen.
