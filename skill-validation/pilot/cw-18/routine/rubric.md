# CW-18 routine: lossless revision in the file deliverable — evaluator only

Test category / supporting purpose: **Effectiveness**.
Primary purpose: apply lossless revision to a detailed durable artifact even though the completion response is brief.
Apply the [routine-suite assessment rules](../../cw-runbook.md#routine-suite-assessment).
Independently read the retained `fixture/clothing-swap-guide.md`; a completion claim is insufficient.

| Invariant | Criterion and pass/fail boundary |
|---|---|
| CW-I2 | Remove content-free introductory and after-example meta prose. Assess repeated token counts, payment instructions and cash/future-swap restrictions for their reader function in the complete revision: useful emphasis or retention is allowed, including reinforcement at token issuance or pickup. Fail demonstrated padding, not the mere survival of a repeated fact or source sentence. |
| CW-I1 | Preserve 13:00 opening, intake until 14:00 and pickup until 15:00; inspection, clean/wearable acceptance, unaccepted items staying with their owner, and one token per accepted item. |
| CW-I1 | Preserve post-intake sorting to size-labeled tables, separate queues and their checking-versus-choosing rationale. |
| CW-I1 | Preserve one token per chosen item, paid to the pickup volunteer before departure, with no obligation to spend every token. |
| CW-I1 | Preserve the three-item example's inspection/three-token sequence, up-to-three purchases with payment, and choosing two leaving one token without a third-purchase obligation. The worked application has a distinct teaching function; the general payment rule alone does not replace it. |
| CW-I1 | A volunteer can apply event-only tokens, expiry at 15:00, no cash or future credit, and no extension for someone who started earlier and still has a token. An integrated explanation can preserve this closing lesson without a separate one-token example. |
| CW-I1 | Preserve remaining accepted clothing going to the community cupboard and donors not retrieving their original accepted items. |
| CW-I1 | Add no unsupported event rule, exception or local detail. |

Keep explanatory examples while removing sentences that merely announce or restate what those examples illustrate.
Reinforcing an important instruction can be useful without adding a fact, numerical example or separate action; do not require novelty as evidence of value.
The file must satisfy both conservation and removal; the completion notice is assessed only for task fidelity/readability.
Only the named file may be created; every original fixture file is protected.
A missing file leaves semantic behavior unassessed and fails deliverable fidelity; do not score response prose as if it were the file.
Copying the whole supplied draft to the file fails CW-I2 even with a perfect completion notice.
