# Access-link guide

## What an access link does

An access link is a single-use URL that expires 30 minutes after issue.
It opens one recipient's report without giving that recipient an account.
An administrator issues the link from the recipient's report page.
The link carries access to that report, so send it only to the intended recipient.
This guide explains what access links do and how staff should use them.
In other words, an access link is a URL that works once and stops working 30 minutes after it is issued.

## Issuing and sending

Check the recipient's address against the request before sending a link.
The report page's address is a suggested destination, not confirmation that the request names the same person.
If the addresses differ, ask the requester to resolve the difference before issuing the link.
Send the link directly to the confirmed recipient, not to a shared team mailbox.
Record the report ID and issue time in the support ticket; do not paste the URL into the ticket, because anyone reading it could open the report.
This section describes the process for issuing a link and sending it to the correct person.

## What the recipient sees

The page shows the report name before the recipient chooses Open report.
Displaying that page does not consume the link; successfully opening the report does.
A network failure before the report opens leaves the link unused, but does not extend its expiry time.
Closing the report after a successful open does not restore the link.
An access link is a single-use URL with a lifetime of 30 minutes from issue.
For example, a link issued at 11:00 expires at 11:30 even if a failed connection delayed the recipient's first attempt until 11:25.

## Troubleshooting a failed open

Ask whether the report previously opened successfully and compare the current time with the ticket's issue time.
If it opened successfully, the link is used; if 30 minutes have elapsed since issue, it is expired.
In either case, an administrator must issue a new link from the report page.
For a connection failure while the link is still unused and unexpired, the recipient can retry the same link.
Before sending a replacement, confirm the intended recipient again and send only to that person; a forwarded support conversation may include other addresses.
Never put the replacement URL into the ticket: record the new issue time instead.
The new link must be issued by an administrator when the original link has expired.

## Quick check before sending

Confirm the recipient, send directly, and record the issue time without recording the URL.
For a failed open, use Troubleshooting a failed open to distinguish a retry from a replacement.
