# CW-06: Trim inflated emphasis without weakening obligation — evaluator only

**Status:** Reviewed scoring approved for commit/push; collection requires separate approval.
Test category / supporting purpose: **Effectiveness**.
Task: [approved prompt](../no-dd/prompt.md).
Apply the [prospective scoring rules](../../cw-runbook.md#prospective-scoring).
Baseline anchors: Emphasis/hedge inflation; deliberate reinforcement exception.

## Preservation (CW-I1)

- Every request must include an API key, the key belongs in the Authorization header, and requests without a key are rejected. Do not introduce optional keys, alternate locations or a narrower class of requests.

## Economy (CW-I2)

- Remove empty intensification or accidental restatement where it adds no information or useful emphasis. Inspect the doubled universal phrasing and repeated rejection clause; no particular word, bold span or repetition is automatically forbidden.

## Reading and task notes

Readability focus: the universal requirement and consequence remain easy to recognize. Effective emphasis is permissible; weakening the rule to save words is not.
