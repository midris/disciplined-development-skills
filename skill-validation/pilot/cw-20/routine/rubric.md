# CW-20 routine: restraint under a tightening request — evaluator only

Test category / supporting purpose: **Effectiveness**.
Primary purpose: preserve an already-effective passage when asked to tighten it.
Apply the [routine-suite assessment rules](../../cw-runbook.md#routine-suite-assessment).

| Invariant | Criterion and pass/fail boundary |
|---|---|
| CW-I1 | Preserve return to the issuing desk before its closing, east 17:00 and west 18:00, and no deadline extension by changing desks. |
| CW-I1 | Preserve the inability-to-reach-desk condition, calling the coordinator via the key-tag number before the deadline, and the coordinator arranging the handoff. |
| CW-I1 | Preserve that voicemail is not confirmation and the borrower keeps the key until both recipient and location are confirmed. |
| CW-I1 | Preserve the letter-slot prohibition and its public-corridor versus locked-office rationale. |
| CW-I1 | Preserve the example's application: an east-desk key returned at 17:30 needs a previously arranged handoff despite the west desk being open. A comparably explicit example between the two closing times is acceptable; a general deadline rule alone loses the illustration. |
| CW-I1 | Add no unsupported return route, exception, penalty or contact detail. |

An unchanged notice passes the semantic criteria and is a valid response to this request.
Equivalent editing also passes if every protected function remains and readability does not materially worsen.
CW-I2 has no removal target here; mark it N/A rather than awarding padding-removal credit or requiring an edit.
Do not use a word count or byte-for-byte match as a criterion.
This case catches destructive editing of supplied prose; CW-17 instead catches failure to generate explicitly requested explanation from notes.
