### Task 1: Make nightly digest delivery bounded, isolated, rate-limited, and retry-safe

**Merge boundary:** One PR containing the complete, independently testable digest reliability change.

**Files:**

- Modify: `src/nightly_digest.py`
- Test: `tests/test_nightly_digest.py`

**Interfaces:**

- Preserve the existing digest content and account-enumeration behavior.
- The orchestration entry point must accept an injected UTC clock and worker identifier for deterministic scheduling and lease tests.
- Analytics pagination must expose the account ID, account-local date, current cursor, page events, and next cursor.
- Delivery state must support a durable `(account_id, local_date)` claim with an expiry, completion recording, and claim release after failure.
- Every send must use the stable idempotency key `nightly-digest:{account_id}:{local_date}`.
- The sender must provide persistent idempotency for that key; this is required to prevent duplication when a worker loses its claim after the API accepted a message but before completion was recorded.
- The rate limiter must coordinate across workers under one shared digest scope and admit no more than 100 sends in any 60-second window.
- Report sent, empty, already-completed, concurrently-claimed, malformed-event, and failed-account outcomes without converting account-local failures into job-wide failures.

**Pinned edge behavior:**

| Input or failure | Required outcome |
|---|---|
| Missing or invalid IANA account timezone | Record an account failure; do not fetch or send; continue with other accounts. |
| Previously completed account/local-date key | Skip fetching and sending. |
| Another worker holds an unexpired claim | Skip that account without sending. |
| Expired claim after a worker crash | Retry using the same idempotency key. |
| No events, or only malformed events | Send nothing and mark the account/local-date complete. |
| Malformed individual event | Count and skip it; continue processing the page and later pages. |
| Malformed page envelope, fetch exception, or repeated pagination cursor | Fail and release that account’s claim; continue with other accounts. |
| Send failure or ambiguous response | Release the claim for retry; reuse the same idempotency key on retry. |
| Millions of events | Consume one page at a time and retain only one page plus the digest’s fixed-size aggregate state. |
| Upstream page larger than its documented page-size limit | Accepted invariant: memory remains bounded by that single upstream page, not by total event count. |
