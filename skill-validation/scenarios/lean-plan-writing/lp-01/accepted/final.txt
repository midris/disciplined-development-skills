# JSON Report CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add JSON report output while preserving existing text behavior.

**Architecture:** Extend the existing format validation and rendering flow in `src/report_cli.py`. Keep text as the default and serialize JSON through Python’s standard library.

**Tech Stack:** Python, `argparse`, standard-library `json`, pytest

**Spec:** `fixture/context/task.md`

## Global Constraints

- Supported formats are exactly `text` and `json`.
- JSON output contains only string `path` and integer `line_count`.
- Unsupported formats write `unsupported format` to stderr and exit with status 2.
- Default and explicit text output remain unchanged.
- Existing path handling, line-count semantics, and all other command behavior remain unchanged.
- Add no external dependencies.

- [ ] **Step 1: Add failing CLI tests**

Cover these behaviors:

| Invocation | Expected result |
|---|---|
| `report PATH` | Existing text output and successful status remain unchanged |
| `report --format text PATH` | Same output as the default invocation |
| `report --format json PATH` for a known multi-line file | Status 0; stdout parses as one JSON object whose `path` equals the supplied path string and whose integer `line_count` equals the existing count |
| `report --format yaml PATH` | Status 2; stdout empty; stderr contains `unsupported format` |

Also assert that the JSON object has exactly the `path` and `line_count` fields.
