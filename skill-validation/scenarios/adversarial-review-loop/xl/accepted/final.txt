Decision: this is a shared-root pattern, not scattered findings. The invariant is: every persistence failure must become a typed, recoverable error with its cause preserved—never a crash, ignored failure, false success, or accepted corruption. Because the axis is visible below the three-cycle cap, audit and repair it now rather than waiting for another review.

Scope: project-wide, across every Swift, Python, and Go persistence path—not merely files or components previously cited. Include storage interfaces and implementations, repositories, serializers, database and filesystem adapters, transaction helpers, caches that write through, background workers, import/export and migration code, startup recovery, RPC/FFI boundaries, and all callers that translate or consume persistence errors. Cover create, read/decode, update, delete, batch operations, commit/rollback, flush/sync/close, retries, recovery, and corruption detection.

Look for:

- Swift: `try!`, `try?`, force unwraps/casts, `fatalError`, assertions used for runtime failures, empty or overly broad `catch` blocks, discarded `Result` values, unchecked database/filesystem return values, unobserved `Task` failures, and `NSError` bridging that loses type or cause. Verify all paths throw or return a domain `PersistenceError`, preserve the underlying error, reject invalid decoded state, and leave transactions/files atomically recoverable.
- Python: `except: pass`, broad catches returning defaults or success, `assert`/`sys.exit` on runtime persistence failures, unchecked `commit`, `flush`, `fsync`, `close`, serialization, rename, and transaction operations, plus background-task exceptions that are never observed. Require domain exception subclasses, `raise ... from ...` cause chaining, rollback/cleanup without masking the primary failure, and explicit corruption errors rather than defaulting malformed data.
- Go: discarded errors (`_`), unchecked `Write`, `Close`, `Sync`, `Rename`, `Exec`, `Commit`, `Rollback`, `rows.Err`, scanner and codec errors, `panic`, `log.Fatal`, `Must` helpers, deferred cleanup errors, short writes, and error wrapping that breaks `errors.Is`/`errors.As`. Require typed or sentinel-compatible persistence errors, `%w` cause preservation, atomic update semantics, and correct handling of commit-versus-rollback failures.
- Cross-cutting boundaries: ensure adapters do not translate failures into empty values, booleans, or success responses; retries do not hide permanent failures; cleanup errors do not overwrite primary errors; partial writes cannot be treated as success; and corrupt or incompatible stored data is surfaced distinctly from “not found.”
