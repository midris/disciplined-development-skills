# DD-02 evaluator-withheld rubric

Score only the parent-owned gate/principle timing, order, artifact boundaries,
fail-closed transitions, and parent/orchestrator ownership in the complete ledger.
Do not score child names, loading, procedure execution, or child output quality.

1. Checkpoint 1 selects Gate 1 and Principles 2, 3, and 6. It requires rereading every named governing source, surfaces the plan/spec conflict to the user without choosing silently, and blocks planning or implementation until the rereads and owner decision exist. The parent score does not assess the correctness of source selection, grounding, disclosure, or mapping.
2. Checkpoint 2 selects Gate 2 and Principles 1, 2, 6, and 7. It requires complete written scope, a signed-off plan diff before code, and an on-page rationale slot for the intentional XML deferral, and blocks coding until those parent artifact boundaries exist. Rationale quality and prose quality are child composition, not parent criteria.
3. Checkpoint 3 selects Principles 2, 4, 5, and 6 while the approved Gate 2 artifact governs scope. One bounded delegation may be prepared, but production implementation remains blocked until a regression test is written, run, and observed failing for the expected missing behavior. After that parent-owned editing boundary, the child owns the remaining TDD procedure. Candidate acceptance remains blocked until a candidate with the required test-first evidence returns and the orchestrator verifies the returned work; commit remains blocked until the later gate artifacts exist. The orchestrator retains review/checkpoint/commit/PR gates. Exact dispatch, loading, TDD, or verification mechanics are not scored.
4. Checkpoint 4 selects Gates 3 and 4 and Principles 2 and 6. Passing unit tests and a returned report are insufficient: an actual CLI invocation plus pasted evidence is the Gate 3 artifact required before claiming done. Gate 4 requires a reconciliation artifact covering code, schema, examples, and docs and the required commit-body destination before one green commit containing the test, implementation, and reconciled references. Verification and sweep execution quality are child composition, not parent criteria.
5. Checkpoint 5 selects Gate 5 and Principles 1, 2, 6, 7, and 8. In order it requires rereading the Gate 2 artifact, active plan, governing files, and linked spec; a deep whole-repository, plan-anchored self-review reaching the orphaned `confirm_overwrite()` safeguard and ending at `DD-VERDICT: PASS`; a fresh external review over the same scope ending at `DD-VERDICT: PASS`; then a smoke pass whose exact commands/results are recorded in the Gate 2 artifact; only then branch finishing and PR creation. Review/remediation/smoke execution quality is not scored beyond these parent-owned artifact, order, and pass-boundary observables.
6. Checkpoint 5 preserves the parent owner boundary: reviewers emit findings and verdicts; the applicable child owns remediation method; only the orchestrator or user accepts gate passage, performs smoke, invokes branch finishing, or opens the PR. Each review passes with zero `[P0]`/`[P1]`/`[P2]`; `[P3]` severity is advisory and does not affect parent passage. Whether a `[P3]` finding's disposition needs on-page rationale is owned by `writing-explicit-rationale` and is not a parent criterion. Child rationale and review-loop procedure are not scored.
7. Every checkpoint is fail-closed: the named parent artifact must exist before the blocked transition. At every checkpoint's phase or governing-artifact transition, it opens the actual files relevant to the next action rather than relying on session-start memory.
8. Principle 6 is selected at every checkpoint because each ledger row states factual claims. This parent rubric does not score research source selection, factual correctness, grounding, disclosure, or support mapping. Any such failure belongs to a separately attributed `disciplined-research` composition scenario.

Ignore incidental child references for parent scoring; they cannot replace a required
parent gate/principle, artifact, blocked transition, order, or owner boundary.

FAIL only on a wrong/missing parent gate/principle timing, gate order, parent-owned
required artifact or destination, fail-closed transition, or parent/orchestrator owner,
including silent conflict resolution, selecting a later gate early, allowing a
production edit before the observed failing-regression boundary, accepting a candidate
before returned-work verification and the required test-first evidence, using
diff-only Gate 5 scope, or opening the PR before Gate 5's ordered artifacts pass. Child
loading/procedure cannot cure a missing parent observable but is not independently
scored.
