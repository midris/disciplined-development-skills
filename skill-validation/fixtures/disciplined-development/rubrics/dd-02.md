# DD-02 evaluator-withheld rubric

PASS only if the checkpoint ledger does all of the following:

1. Checkpoint 1 re-reads every named governing source at session start, uses `disciplined-research` before relying on the library claim, surfaces the plan/spec conflict to the user without choosing silently, and blocks planning or implementation until those Gate 1 artifacts and the decision exist.
2. Checkpoint 2 creates written scope bullets and a signed-off plan diff before code under Gate 2; invokes `superpowers:writing-plans` and routes plan structure to `lean-plan-writing`, on-page necessity judgment for the XML deferral to `writing-explicit-rationale`, and the padded operator note to `concise-writing`; it blocks coding until the written artifact and signoff exist.
3. Checkpoint 3 invokes `superpowers:subagent-driven-development`, `superpowers:test-driven-development`, and `dispatching-development-subagents`; requires the subagent to load the parent and re-read governing files while retaining review/checkpoint/PR gates with the orchestrator; and requires test-first editing with an observed failing regression followed by implementation/refactor and a green uncommitted candidate diff.
4. Checkpoint 4 invokes `superpowers:verification-before-completion`, treats passing unit tests and the returned report as insufficient, and requires an actual CLI invocation plus pasted evidence before claiming done under Gate 3; it routes `output_mode` through `sweeping-stale-references` across code, schema, examples, and docs before authorizing one commit containing the test, implementation, reconciled references, and a `References swept:` commit-body artifact under Gate 4.
5. Checkpoint 5 re-reads the Gate 2 artifact, active plan, governing files, and linked spec; invokes `superpowers:requesting-code-review` and starts with a deep whole-repository, plan-anchored self-review using `adversarial-review`; explicitly reaches outside the current diff and surfaces the orphaned `confirm_overwrite()` safeguard; routes blocking remediation through `adversarial-review-loop`; then obtains a fresh external review over the same scope and only then performs a smoke pass whose commands and results are recorded in the Gate 2 artifact before invoking `superpowers:finishing-a-development-branch` for PR creation.
6. Checkpoint 5, read across its action/artifact, owner, and blocked-next-action cells, states self-review/remediation to `DD-VERDICT: PASS`, fresh external review/remediation and rerun to `DD-VERDICT: PASS`, smoke commands/results recorded in the Gate 2 artifact, then PR; each pass has zero P0/P1/P2 while P3 is advisory; reviewers emit review verdicts, while only the orchestrator or user accepts gate passage, performs the smoke pass, invokes the finishing skill, or opens the PR.
7. Every checkpoint is fail-closed: the named artifact must exist before the blocked next action. The sequence reflects the Iron Law and Principles 1-6 and 8, including rereading again at the major Gate 5 transition rather than relying on session-start memory.
8. Across the sequence, all eight repository companions and every required Superpowers methodology named above are selected at their actual boundary, while detailed research, planning, rationale, concision, dispatch, sweep, review, and remediation mechanics remain with the child skills rather than being restated.

FAIL on any missed criterion, reordered gate, silent conflict resolution, tests-after implementation, diff-scoped final review, or attempt to delegate an orchestrator-owned gate.
